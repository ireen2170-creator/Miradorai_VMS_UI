# 🔐 Encryption Key Backup & Recovery Guide

## Overview

Your VMS system uses **AES-256-CBC encryption** to secure recorded video files. The encryption key is critical:

- **Without it**: You cannot decrypt ANY encrypted recordings
- **One key for all**: All recordings use the same master key
- **If lost**: Data becomes permanently unrecoverable

## Key Location

| Environment | Path |
|-------------|------|
| **Docker Container** | `/app/data/video.key` |
| **Docker Named Volume** | `app_data` (managed by Docker) |
| **Host Backup** | `./backups/video.key.backup-*` |

## 🛡️ Backup Strategy

### Automatic Backup (Recommended)

Schedule the backup script to run daily:

#### Windows Task Scheduler
1. Open **Task Scheduler**
2. Create Basic Task:
   - Name: `VMS Encryption Key Backup`
   - Trigger: Daily at 2 AM
   - Action: `powershell -ExecutionPolicy Bypass -File "D:\Kiru\VMS\Mirador_VMS_UI\scripts\backup-encryption-key.ps1"`

#### PowerShell Scheduled Job
```powershell
$trigger = New-JobTrigger -Daily -At 2:00AM
Register-ScheduledJob -Name "VMS-Key-Backup" `
  -ScriptBlock { 
    & "D:\Kiru\VMS\Mirador_VMS_UI\scripts\backup-encryption-key.ps1" 
  } `
  -Trigger $trigger
```

### Manual Backup

Run anytime:
```powershell
.\scripts\backup-encryption-key.ps1 -BackupDir "D:\Secure\VMS-Backups"
```

## 🔄 Recovery Procedures

### Scenario A: Container Deleted/Recreated

The named volume `app_data` automatically preserves the key.

```bash
# Simply restart containers
docker-compose down
docker-compose up -d

# Key is restored automatically from app_data volume
```

### Scenario B: Docker Volume Corrupted

1. **Stop containers**:
   ```bash
   docker-compose down
   ```

2. **Restore from backup**:
   ```powershell
   .\scripts\restore-encryption-key.ps1 -KeyFile "backups\video.key.backup-20250323_143000"
   ```

3. **Restart containers**:
   ```bash
   docker-compose up -d
   ```

### Scenario C: Complete System Loss

1. **Set up new VMS system** (install Docker, clone repo)

2. **Create `app_data` volume**:
   ```bash
   docker volume create app_data
   ```

3. **Restore key to volume**:
   ```powershell
   .\scripts\restore-encryption-key.ps1 -KeyFile "C:\secure-backup\video.key.backup"
   ```

4. **Start containers**:
   ```bash
   docker-compose up -d
   ```

## 🚨 Critical Warnings

| Scenario | Impact | Prevention |
|----------|--------|-----------|
| Key deleted from container | ❌ Cannot decrypt recordings | ✅ Use named volume (auto-persistent) |
| Docker volume deleted | ❌ Key lost unless backed up | ✅ Maintain secure off-site backups |
| Key file corrupted | ❌ Cannot decrypt recordings | ✅ Keep multiple backup copies |
| Recordings lost | ⚠️ Can't recover from backup | ✅ Backup `C:/recordings` separately |

## 📞 Support & Troubleshooting

**Q: How do I know the key is being used?**
```bash
docker logs mirador-backend | grep -i "encrypt\|key"
# Look for: "✅ AES-256 key loaded successfully"
```

**Q: Can I change the key?**
```
❌ Not recommended. Changing the key will make all existing recordings unreadable.
   Generate a new key only if you:
   1. Delete all old encrypted recordings
   2. Accept data loss
```

**Q: What if I lose all backups?**
```
❌ Unfortunately, data is unrecoverable.
   All encrypted recordings become permanently inaccessible.
   This is by design for security.
```

**Q: How large is the key file?**
```
32 bytes (256 bits) - Very small, easy to backup
```

## 🛠️ Docker Compose Configuration

```yaml
volumes:
  app_data:      # ✅ Named volume - persists encryption key
  mongo_data:    # ✅ Named volume - persists MongoDB data

services:
  backend:
    volumes:
      - app_data:/app/data              # Key stored here
      - C:/recordings:/recordings       # Video files here
```

**Persistence behavior**:
- ✅ Container deleted → Key persists in `app_data` volume
- ✅ Container recreated → Key automatically available
- ✅ System reboot → `app_data` volume preserved
- ⚠️ Volume deleted → Key loss (must restore from backup)
